# 📦 三胜达进销存

电脑和手机共用的库存网页，GitHub Pages 托管界面，Supabase 保存共享数据。当前功能聚焦客户、商品、入库、出库和库存，不要求录入价格。

使用地址：**[三胜达进销存](https://meaning11451.github.io/inventory-app/)**。电脑和 iPhone 都打开这个网址；当前按用户选择免账号使用，共用同一份云端账本。查询最新库存、保存进出库和同步数据都需要联网。

## ✨ 功能

- 📦 **库存查询** - 实时库存，搜索过滤
- 📂 **期初库存** - 读取管家婆“库存状况”表，核对后结转到新账
- 📥 **入库管理** - 表单录入 / 快捷粘贴批量录入
- 📤 **出库管理** - 表单录入 / 快捷粘贴批量录入
- 👤 **客户管理** - 自动补全，按客户查账
- 📋 **记录查询** - 入库/出库历史，按日期和客户筛选
- ⚙️ **商品管理** - 增删改查
- 📱 **PWA** - 支持添加到桌面；进出库记录请联网保存
- 🔄 **双端同步** - 手机电脑数据实时同步

## 🚀 自行部署

使用上面的现有网址无需重新建库；以下步骤供另建项目时参考。

### 1. 注册 Supabase（免费数据库）

1. 打开 [supabase.com](https://supabase.com)，用 GitHub 账号登录
2. 点击 **New Project**
3. 输入项目名称（如 `inventory`），设置数据库密码（记下来）
4. 选择离你最近的区域（如 `ap-southeast-1` 新加坡）
5. 点击 **Create Project**，等 1-2 分钟初始化完成

### 2. 创建数据库表

1. 在 Supabase 项目左侧菜单，点击 **SQL Editor**
2. 点击 **New Query**
3. 复制粘贴 `supabase/migrations/001_schema.sql` 的全部内容
4. 点击 **Run** 执行

随后按编号执行 `002_inventory_backup.sql`、`003_inventory_order_and_whole_quantities.sql` 和 `004_product_aliases.sql`。已有项目只执行尚未应用的迁移：003 增加自动追加的 `display_order` 顺序列、按调用者权限读取的库存视图和整数数量约束；004 增加共享的 `products.aliases` 文本数组。商品别名由账本资料配置，迁移不内置具体商品或别名。应用 003 前需核对并处理旧账中的小数数量，不能靠四舍五入通过约束。

### 3. 配置 API 密钥

1. 在 Supabase 项目左侧菜单，点击 **Settings** → **API**
2. 复制 **Project URL** 和 **anon public key**
3. 打开 `js/supabase.js`，替换以下两行：

```js
const SUPABASE_URL = 'YOUR_SUPABASE_URL';       // 替换为 Project URL
const SUPABASE_ANON_KEY = 'YOUR_SUPABASE_ANON_KEY'; // 替换为 anon key
```

### 4. 部署到 GitHub Pages

1. 把代码推送到 GitHub 仓库：

```bash
cd inventory-app
git init
git add .
git commit -m "初始化进销存系统"
# 在 GitHub 创建仓库后：
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
```

2. 在 GitHub 仓库打开 **Settings → Pages**，选择从 `main` 分支的根目录发布
3. 发布完成后使用 Pages 提供的网址；本项目现有地址为 [https://meaning11451.github.io/inventory-app/](https://meaning11451.github.io/inventory-app/)
4. 电脑和手机使用同一网址，安装方法见下方说明

### 5. 预览与构建品牌图标

安装到桌面或手机主屏幕的图标使用用户提供的绿色、黄色 SAN SHENG DA 原商标，保留原有文字、颜色和边框，不重画。重新构建命令为：

```sh
node scripts/build-app-icons.mjs <source.jpg>
```

将 `<source.jpg>` 替换为原图路径；当前原图保存在 `.impeccable/assets/app-icon-source.jpg`，不随网站发布。脚本的裁切坐标针对这张 2048×2048 原图设置，仅裁去外围空白，再按原比例缩放并居中放在白底上；换用其他原图时须重新核对裁切范围。输出为 `icons/app-icon-180.png`、`icons/app-icon-192.png`、`icons/app-icon-512.png` 和 `icons/app-icon-maskable-512.png`；maskable 版本的商标留在中央安全圆内。来源与处理记录保存在 `icons/app-icon-provenance.json`，输出 PNG 同时嵌入来源元数据。

网页内部的品牌徽记和浏览器 favicon 沿用原有素材。在浏览器中打开 `icons/generate.html`，可预览和下载这套徽记；它轻量采用招牌的绿色与椭圆形状，不含电话、地址和整张招牌。需要从其高分辨率母图重新生成尺寸时：

```sh
npm run icons:build -- <master.png>
```

将 `<master.png>` 替换为母图路径。这套网页品牌素材由 `image_gen.imagegen` 生成，完整提示词和来源记录分别保存在 `icons/brand-prompt.txt`、`icons/brand-provenance.json`；其 PNG 嵌入来源元数据，重新构建后也需保留该记录。本地母图位于 `.impeccable/assets/brand-master.png`，不随网站发布。这套素材不再用于安装后的桌面或主屏幕图标。

## 📱 快捷录入格式

支持直接在文本框粘贴以下格式：

```
客户名 商品名 数量 单位
```

**示例：**
```
张三 后腿卷 10件
李四 三号 8
乌鸡卷 3件
精品五花 5kg
```

- 每行一条记录
- 客户名可选（如果不写，可以使用顶部的"整批客户名"）
- 单位可选（默认使用商品的单位）
- 自动匹配已有商品并在预览下拉框中选中；未匹配或对应多个规格时，须手动选择已有商品，快捷录入不会新建商品

## 库存顺序、数量与识别规则

- 库存按持久保存的 `display_order` 排列，当前账本沿用原 Excel 的 27 行顺序；新增商品自动追加到末尾。
- 库存页在列表上方显示总库存和商品数。搜索只筛选列表并显示命中数，总库存仍汇总全部商品；不同单位分别合计，不直接混加。
- 单笔、快捷粘贴、日常 Excel、期初库存和库存修正都只接受整数，不自动取整或四舍五入。日常入库、出库数量必须大于零；期初库存和库存修正可为零或负整数。斤、公斤等单位同样遵守整数规则。
- 商品先匹配完整名称，再匹配账本中明确配置的别名；完整名称优先，不按品牌名或商品名的局部片段猜测。别名随云端商品资料在电脑和手机间共享，预览显示匹配后的规范全名。
- 已确认的简称规则为“5斤三号”对应“五斤三号”；“三号”仍对应“三号”，两者不合并。
- 已有客户匹配兼容全角半角、空白和逗号等分隔符；两个用逗号分隔的名称部分可交换顺序，也可省略已有名称末尾的“数字排数字号”。仅唯一匹配时自动选用；有多个候选时提示核对并阻止直接新建，避免产生重复客户。

## 客户分组快捷录入

客户单独一行，之后每行一个商品，直到下一个客户标题。客户中的地区、逗号会保留：

```text
小寨，田志强
后腿卷 15件

济南，武
合胜源后腿卷 20件
合胜源一号 5件
合胜源后腿砖 5件
三胜达后腿卷 10件
```

点击“解析预览”，核对可编辑表格后保存。商品栏使用下拉框，列出已有商品的规范名称、规格和单位；已匹配的商品会预先选中，可直接改选。同名不同规格也可在此选择，无需切换到单笔表单。客户、数量和单位可更正，预览行可删除；修改原文后需要重新解析。日常 Excel 导入使用同样的预览流程。

- 商品优先按完整名称匹配，再匹配明确配置的别名；忽略大小写、全角半角和多余空白，不按部分名称合并品牌。
- 不同品牌的后腿卷会分别保存。未匹配或有多个候选的商品显示“请选择商品”，必须从下拉框选择；真正的新商品请先在库存页添加，再重新解析。
- 改选商品保留本行的客户和数量，并将单位更新为所选商品的单位；简称或未匹配名称仍显示在商品栏下方的“原文”中，便于核对。
- 小数、零数量、负数、缺少商品或数量的日常预览行必须更正或移除，整批才能保存。
- 已有商品的单位不同时必须先核对，系统不会把“箱”当成“件”直接加减。
- 保存前重新读取商品资料，按所选商品编号核验整批记录。未选商品或商品已被删除时，整批停止，不会先写入客户或进出库记录。快捷录入和日常 Excel 导入都不会自动新建商品；未匹配的客户仍可在保存时新建，但对应多个已有客户时必须先核对。
- 保存失败时保留原文和预览；保存期间禁用提交按钮，避免双击重复登记。
- 入库、出库页的 Excel 导入用于日常登记；管家婆现有库存请使用库存页的“导入期初库存”。

## 从管家婆结转期初库存

入口：**库存 → 导入期初库存**。先按“创建数据库表”完成所需迁移。

1. 选择管家婆导出的“库存状况” `.xls` 或 `.xlsx` 文件。允许表头上方存在标题、公司资料和空行；有多个库存工作表时可以选择。
2. 核对商品、规格、单位、数量和结转日期。预览可以直接修改；原文件不会改变。缺少单位时，逐行填写，或用“只补空单位”统一补充。
3. 点击“核验现有账本”。同名同规格商品按完整名称匹配，不会按部分名称合并品牌；单位不一致、重复商品或已有日常进出库的商品会被拦住。
4. 核对负库存并勾选确认项，结转期间暂停其他进出库登记，再点击“确认导入期初库存”。选文件和核验都不会写入账本。

适配“行号、商品编号、商品名称、单位、库存数量、成本均价、库存金额、期初数量……”这类导出表，读取的是 **库存数量**，忽略旧账的期初数量、金额、成本和售价。商品编号仅供预览核对，商品按名称和规格匹配。经营历程报表不能作为库存导入；旧经营记录继续保留在原电脑查询。

- 空数量会报错，不会自动变成零。零库存只登记商品，不生成零数量流水。
- 期初库存仍会在确认导入时新建账本中缺少的商品；这是结转流程的行为，日常快捷录入和日常 Excel 导入只使用已有商品。
- 负库存不会被改成零，需明确确认后按原负数结转。
- 相同商品和数量再次结转会跳过；已结转但数量不同会拦住，不能用重复导入覆盖原期初库存。
- 每个商品使用固定的期初记录编号，网络中断后可以重新核验并重试，已保存的记录不会重复累计。正数、负数和商品资料分批保存，不能当作一次数据库事务；出错时清单会保留。
- 期初库存计入当前库存，单独标记为“期初库存（管家婆结转）”，不计入今日入库、今日出库和普通经营记录。

Excel 读取组件沿用 SheetJS CE 0.18.5，随网站一并发布，来源和许可证见 `vendor/`。原始账表和本地模拟账本不随网站发布。

## 在电脑和 iPhone 上使用

电脑浏览器和 iPhone Safari 都打开 **[三胜达进销存](https://meaning11451.github.io/inventory-app/)**。1024px 及以上宽度使用左侧导航和宽表格，手机使用底部导航；两端共用同一份云端数据，无需分别导入。

若安装后的图标仍显示旧样式：iPhone 可能需要移除原来的主屏幕快捷方式，再用 Safari 重新添加；Android 的更新行为取决于浏览器，较新的 Chrome 可能提示确认图标更新，需要立即替换时可移除后重新添加。移除和重新添加快捷方式不会清空云端账本。

## 下载完整账本备份

首页的“备份到本机 → 下载完整备份”会生成包含商品、客户、全部进出库记录和库存核对信息的文件。iPhone 可选择“存储到文件”，电脑由浏览器下载保存。只有确认文件已保存到设备后，才算留好了这份副本。

本机仍有待同步记录时会阻止导出，请先联网完成同步；无法读取待同步队列时也不会生成备份，请刷新页面后重试。

`supabase/migrations/002_inventory_backup.sql` 为现有项目增加一次读取完整快照的函数；新建或迁移项目时在原建库脚本后执行。函数沿用调用者权限，不绕过行级策略；库存视图也按调用者权限读取。它只查询账本，不会修改云端数据。导出不受普通列表每页数量的限制，生成文件前会核对数量、关联、重复编号以及库存与流水的一致性。

备份属于应用数据备份，不包含 Supabase 项目设置或登录凭证。它保留原始编号、业务日期、备注和历史客户名称；后续需要恢复时应先核对目标账本，按商品、客户、入库、出库的顺序恢复。当前不提供会覆盖现有账本的一键恢复按钮。
